# 小工作区兼容与验证边界

连接前读取游戏所在显示器的 `rcWork`，在物理像素 DPI 上下文中测量客户区与外框差，扣除边框和标题栏，再选能完整显示的最大已验证档位：1920×991、1600×826、1440×743、1280×661。不会修改 Windows 分辨率或显示缩放。

标准窗口已有完整可见的 1920×991 客户区时保持不动。1920 宽显示器原有的不可见左右边框对齐仍保留；缩小档位要求整个外框能放入工作区。负坐标副显示器、任务栏占用、窗口最小化和最大化均参与核验。调整只发一次尺寸请求，并在 3 秒内要求两次稳定尺寸和客户区完整可见；游戏拒绝目标尺寸、显示器在调整中改变或窗口身份变化会停止。

先计算尺寸上限，再向下选档是实际识别验证后的决定：1335×689 的游戏能正确显示，但部分商店文字无法通过现有模板阈值；不能因为宽高比相同就假设所有字体栅格化结果相同。低于 1280×661 加实际边框所需工作区时明确提示，目前不宣称更小窗口兼容。

截图仍使用 MaaFramework 5.13.1 的短边 720 归一化。典型截图宽度为 1394 或 1395；识别框、ROI、偏移、拖动使用这一坐标空间，点击交给 Maa 换算到实际客户区，不能再额外乘一次缩放比例。运行中若手动改变窗口尺寸，会停止旧坐标操作，重新连接后再选择尺寸。

模板仅补充实机小窗口中的局部控件，不替换原图或降低阈值。地下城导航仍为 0.95，OCR 仍为 0.95，关闭/奖励等原来更高的阈值保持原值。新增模板同样保留 ROI、亮度/对比度和附加上下文检查；选中导航模板包含选中圈，副本名称不能互相替代，奖励点击仍需要正确金额和弹窗证据。

验证分层：

- 尺寸策略单元测试：边框差异、负坐标、工作区不足、尺寸拒绝、取消、进程身份变化、调整中换显示器及被裁切客户区。
- 原生 Maa 离线控制器：五组实际像素尺寸的截图归一化及四个点击位置，换算误差不超过 1 像素，测试控制器不接触游戏。
- 本机实际窗口：使用生产尺寸策略和较小的测试工作区预算，真实改变游戏客户区并截图。此项不是在另一台小显示器电脑上测试。
- 实际小窗口画面：导航、名称、详情、工坊、商店与倒计时 OCR；检查错误页面、未选中导航和变暗遮挡反例。完整玩家画面仅留本机诊断目录，不随源码或便携包上传。
- 便携版：移动到包含中文和空格的新目录后执行自检，覆盖原生库、模板、OCR、尺寸策略、Maa 坐标换算和界面初始化。

这些验证不等于每台显卡、每个 DPI、所有战斗房间和数小时连续挂机均通过。遇到未知布局或模板未命中时保留原诊断和停止机制，请提供新版诊断包，不通过降低阈值掩盖问题。
