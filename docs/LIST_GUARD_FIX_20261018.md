# 六本选本超时修复（2026-10-18）

## 诊断与原因

15:02:42 的无进展预警和 15:03:04 的超时截图都停在地下城列表。六本名称的匹配分数为 0.996490，但其附加页面校验使用名称下方的三个骷髅图标，匹配分数仅为 0.942423，低于 0.95 阈值。选本和拖动规则都被同一个校验挡住，最终在 `SelectDungeon` 超时。

15:04:13 的后一次诊断已经处于六本战斗，而脚本状态仍为 `SelectDungeon`。该段执行日志没有选中六本或点击“去探险”的记录，不能根据它确认是谁推进了游戏；本次不将战斗页当作列表，也不自动接管未知来源的副本进度。

## 修复

使用底部带红色选中边框的地下城导航作为列表标识，限定底部区域，匹配阈值 0.95（按用户后续指定），并要求亮度与对比度比值至少 0.85。故障两帧及原有一本至三本列表截图的匹配分数均为 1.0；普通关卡页、战斗页、详情和弹窗遮挡、变暗页面不能通过。

`bk2/list_guard.py` 统一替换 BK2 生成流程中的列表识别条件，包括选本、拖动、关闭详情后的确认、完成/放弃后返回确认和列表 OCR 兜底。`vendor_core` 与基础配置保持原样；副本名称匹配、入口偏移、连续两帧确认、重试上限、详情后继校验和内存完成校验仍生效。

## 验证方式

- 用实际故障截图重现旧校验失败，确认新规则能够识别六本。
- 回放模拟点击，验证连续确认后只点击一次正确入口，看到详情后才推进，不增加通关次数。
- 用普通关卡、战斗、遮挡和变暗截图检查误识别。
- 覆盖六个副本生成配置、列表 OCR、战败放弃流程及完整离线回归。

本机完整结果保存在 `evidence/list_guard_20261018/tests.json` 与 `tests.txt`。公开仓库不含玩家截图，相应回放测试明确跳过。此次修复和测试不发送游戏输入，也不写本地挂机设置和冷却计时。已打开的 BK2 需要重新启动才能加载修复。

初次修复采用 0.97 时的验证结果：本机完整离线回归 **283 项通过、0 失败、0 错误、0 跳过**；发布副本 **186 项通过、97 项明确跳过、0 失败、0 错误**。发布副本的只读 EXE 版本、依赖与模板检查通过。GitHub CI 结果以对应提交的 Actions 记录为准。

后续按用户指定将列表校验调整为 **0.95**，其他规则阈值不变。列表识别、真实截图回放及战败返回的 **19 项相关测试全部通过**；已知普通关卡反例分数 0.945166，仍被拒绝。维护约定已写入 `AGENTS.md`：漏识别优先补充模板或调整识别区域，不直接下调阈值。
