# 黑火守望 v0.1.1

2026-10-18 的公开测试修复版。

## 故障依据

15:34 的诊断显示：完成四轮后等待六本冷却，恢复执行时在创建截图后端、读取客户区尺寸处抛出“游戏窗口客户区无效”。当时没有记录窗口是否最小化；附带截图已旧约 148 秒，不能用它证明故障时的窗口状态。维护期间只读核查时，窗口已正常，尺寸为 1536×792。

原代码只在开始整次挂机时尝试恢复最小化窗口，后续每次副本、奖励或列表 OCR 创建后端时直接读取尺寸，缺少恢复等待。另外，任务配置在后端连接后才写入诊断，导致六本连接失败仍可能携带上一轮三本配置。

## 修复

- 每次创建后端前重新查找绑定进程的可见窗口，验证进程身份，最小化时请求恢复；连续两次客户区有效且尺寸一致后才继续。
- 单次窗口准备最多 3 秒；针对准备检查与后端构造之间的尺寸变化，仅对控制器创建前的指定窗口错误重试一次。不会重复点击，其他连接错误不重试。
- 用户停止、内存失效、窗口身份变化或窗口不唯一时停止。运行中的原有窗口尺寸与截图保护保持有效。
- 诊断增加窗口候选数、句柄、最小化状态、客户区读取结果、尺寸、恢复请求、等待时长和连接尝试结果。连接前先更新当前任务配置，清除上一轮 runner 上下文。
- 唯一代码版本源递增到 0.1.1；Git 标签使用 v0.1.1。未修改识别模板、阈值、用户配置或计时文件。
