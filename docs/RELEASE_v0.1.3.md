# 黑火守望 v0.1.3

2026-10-18 公开测试修复版。

## 放弃冒险的二次确认

用户补充的截图显示：点击“放弃冒险”后，还会出现“现在放弃冒险将无法返回，地下城也将重置”的确认弹窗。旧流程缺少点击此弹窗确认按钮的规则，可能在等待失败画面消失或等待返回列表时停止。

修复后的流程为：当前战斗最多重新开始三次；仍失败则点击放弃冒险，识别专用提示和确认按钮，连续两帧匹配并在点击前重新核对后提交一次确认。确认只在本次执行已发起放弃、三次重试已用完时启用。

确认后必须连续两帧识别到副本列表或主界面，且专用弹窗不再存在；随后仍由原有返回状态及内存退出校验确认副本已结束，交回调度跳过当前副本。本次失败不计为通关，其他已勾选副本、钻石和体力领取继续按原设置执行。没有弹窗而直接返回的旧分支仍可处理。

确认按钮无响应、黑屏、未知页面或停止/暂停时不重复提交确认；未确认退出不当作正常放弃。诊断 history 新增弹窗出现、确认请求、确认后返回三个阶段，counters 记录 `abandon_confirm_requests`，便于定位停在哪一步。

## 模板与证据范围

仅加入放弃提示正文和确认文字两个小模板，阈值为 0.95；列表导航及其他既有识别阈值不变。用户上传的弹窗为裁剪/放大图，结合现有标准截图的同字体“确认”文字校准至约 0.72 倍，生成 410×211 的离线弹窗素材。用于缩放校准的灰度相关性约为 0.99；这不是实机模板命中率。

本地回放将缩放后的弹窗组合到已有失败截图中，并使用真实 MaaFramework 识别、模拟输入执行三次重试、放弃、确认和返回列表。它能验证流程和匹配保护，不能证明游戏实际弹窗的实时捕获尺寸已验证。完整玩家截图及回放素材只保留本机，不上传；公开测试用必要的小模板合成图片验证识别保护。

本次只读查看游戏窗口时，游戏在副本房间；没有操作游戏、发起战斗或点击放弃。

## 验证结果

- 本机 BK2 完整离线回归：335 项全部通过，零跳过。
- 发布副本完整离线回归：335 项中 235 项通过，100 项因未公开玩家截图而跳过，无失败或错误；跳过不算通过。
- 战败、二次确认、放弃后继续调度及列表识别专项回归：48 项通过。
- 两份程序 `--version` 均输出 v0.1.3；`check` 核验游戏文件、依赖和模板通过。
- 本机计划、地下城冷却、体力领取记录与发布副本计划的 SHA-256 均与本次修改前一致。
- 完整日志位于各自副本 `logs/version_0_1_3_regression.txt`，不上传 GitHub。

## 使用

完全退出旧 BK2 并重新打开，确认标题显示“黑火守望 v0.1.3”。停止后直接开始不会重新加载代码。本次维护不修改挂机设置、体力阈值、选本或任何冷却记录。
